API Chain Runner guide

The basics of what is built in, in the order you will use it. Press the ? button on any page for a guided tour of its buttons.

Overview

API Chain Runner runs a list of API calls described in a YAML file. Each call is a step, and a step can use values from the responses of earlier steps. You can run the chain from the command line or from this web UI.

  • Chain calls and pass response values forward.
  • Poll until a field reaches an expected value, and retry failed calls.
  • Pause for a manual step, such as an approval done by a person.
  • See each step's result live, send single requests, and export results to CSV.

Quick start

# run a chain from the terminal
api-chain-runner my_chain.yaml

# open this web UI on a folder of flows
api-chain-runner --ui flow/

Any .yaml file with a chain key in the flow folder shows up on the dashboard.

Your first chain

Use New Flow on the dashboard, or write the file by hand:

variables:
  base_url: "https://api.example.com"

chain:
  - name: auth
    url: "${vars.base_url}/login"
    method: POST
    payload:
      email: "${ENV:AUTH_EMAIL}"
      password: "${ENV:AUTH_PASSWORD}"

  - name: get_user
    url: "${vars.base_url}/user"
    method: GET
    headers:
      Authorization: "Bearer ${auth.token}"

Steps run from top to bottom. name must be unique because other steps use it to refer to this step's response.

Passing values between steps

WriteMeaning
${auth.token}The token field in the response of the step named auth. Nested paths such as ${app.data.id} work too.
${vars.base_url}A value from the variables block at the top of the file.
${ENV:API_KEY}An environment variable. Keeps secrets out of YAML. Manage them with the Environment button.

Step options

Only name, url and method are needed. The rest are optional.

OptionWhat it does
headers, payloadRequest headers and JSON body.
filesUpload files as multipart form data (field: path).
delaySeconds to wait before the step runs.
pollingRepeat the call until a response field (key_path) equals one of expected_values, checking every interval seconds up to max_timeout.
retryRetry on timeouts, connection errors and 5xx. Default is 3 attempts. Use retry: false to turn it off.
conditionRun the step only if an earlier step's response matches a value.
print_keysResponse fields to show beside the step. They refresh live while polling.
eval_keys, eval_conditionPull response values into names and check them with an expression, with a success or failure message.
continue_on_errorSet to false to stop the chain when this step fails. The UI then offers Retry.
manual, instructionA step with no HTTP call. The run waits until you confirm it.

The flow page

Each flow is drawn as a vertical chart of step cards. Card borders turn green, orange or red as steps pass or fail.

ControlWhat it does
Run ChainRuns every step in order.
Ctrl/Cmd + click cardsSelects steps. Run then executes only those and asks for the payload, query and file values they use.
Pause, Resume, StopAppear during a run. Stop ends it at the current step and shows a report of what ran.
RetryShown on a failed stop-on-fail step. Re-runs it and continues with the data collected so far.
Click a cardOpens the edit drawer for URL, headers, payload, polling and retry. Save Changes writes to the YAML.
Add Step pillHover a card to insert a new API or manual step after it.
Edit YAMLEdits the whole file in a code editor.
Step ResponsesAfter a run, a table of every step's status, time and response. Download it as CSV.

Request panel

Click a step in the sidebar list to open a Postman-style window that sends just that one request. You can change the method, URL, params, headers and body (JSON, form-data with file upload, or urlencoded) and read the response with status, time and size. Copy cURL copies the request for a terminal. Nothing you do here changes the YAML.

Environment variables

The Environment button in the sidebar opens your .env file. Add, edit or delete variables, then reference them as ${ENV:NAME}. Values stay hidden until you choose Show values, and changes apply to the next run without a restart.

Flow documentation

Every flow has a Documentation page, reached from the sidebar of the flow. It holds a title, description, group, tags, rich-text notes, authors and a change log, so the team knows what a chain is for.
